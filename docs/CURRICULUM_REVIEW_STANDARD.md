# 课程质量检阅标准

> 本文档定义对存量深化课程（`status: curated`）的定期检阅方法与判定规则。检阅目标是发现内容证据缺口、视觉异常与充分性不足、时间预算失真，以及状态与深度不匹配，并把问题排入修复队列。课程写作与发布规范仍以根目录 `CONTRIBUTING.md`、`docs/CONTRIBUTING_LESSONS.md`、`docs/VISUAL_LESSON_STANDARD.md` 为准；本文档只定义「怎么查、查什么、怎么判」。
>
> 最后更新：2026-08-01

## 1. 检阅触发与范围

- 触发方式：
  1. 自动化五课批次每次开工前，对目标路线与相邻路线的 curated 课程做轻量检阅（至少跑本文档第 2 节脚本化检查项）。
  2. 每完成 5 个批次或用户显式要求时，做一次全站检阅（覆盖全部非 Python curated 课程）。
  3. 任何计划修改某篇已有课程的编辑动作，必须先检阅该篇再改。
- 范围：非 Python 的全部 curated 课程。Python 首轮 102 课按既定规则保留正文、撤回视觉、等待逐模块重构，不作为视觉覆盖对象，不纳入本轮视觉检阅；其内容检阅在重构批次内完成。
- 证据权威：以当前工作树、`curriculum:audit`、官方文档/源码第一方资料为准；检阅结论不依赖聊天记录。

## 2. 内容证据检阅（每课）

### 2.1 机器契约完整性（脚本化）

运行普通课程审计（`curriculum:audit`）覆盖：题名/id/路径一致性、TODO 与模板占位符、章节/变体/积木/源码行数/逐段讲解步数下限、中文密度下限、四段时间合计、视觉双向索引与 placement、资源归属。**审计通过是检阅的前提，但不是充分条件。**

### 2.2 证据核验（审计不覆盖、须人工复查）

逐课检查以下项，任一不满足即记为问题并排入队列：

- **官方入口**：`official.url` 必须带精确章节锚点（`#...`）。例外：官方 API 参考页（如 `reference.langchain.com`）与官方博客单页（如 `vllm.ai/blog/...`）本身没有子锚点时，允许路径级定位，但 `official.note` 必须说明该页约束了什么；不得把此类例外当成普遍许可。
- **源码版本固定**：`source.url` 必须指向真实 tag 或 commit（`/blob/<tag-or-40hex>/`），**禁止 `main`、`master`、`refs/heads/main` 等可变分支**；行区间 `#Lx-Ly` 必须与所固定版本一致（同一 commit 下核验）。发现可变分支 URL 时，必须重新联网核验目标 tag/commit 与该文件行区间，再修改，禁止保留旧行号。
- **源码与正文对应**：`source.symbol`、源码节选与正文主路径必须能一一对应；节选删减处必须说明删掉了什么、失去哪些生产保证。
- **更新日志**：文末必须存在 `## 更新日志` 且最新记录在最上；`human`/`ai`/`at`/`summary` 齐全。历史课程缺日志时，按 `CONTRIBUTING.md` 规则在**下一次实质修改时**补录（有 Git/PR 证据才写），禁止为凑齐而编造。
- **署名纪律**：`ai` 字段必须等于该课实际创建/修改时的运行模型；**修改专题时追加新记录，禁止改写、删除或压缩已有记录**。历史批次的模型名（如 `WorkBuddy · Hy3`）是审计事实，检阅不得「顺手统一」。
- **跨课复制**：抽样对比同路线相邻课程的章节结构与示例代码；发现「同模板换名」或大段复用即记为问题。

### 2.3 检阅脚本

可用脚本采集硬数据（供人工复核，不替代人工）：

```bash
node --experimental-strip-types <review-script>.mjs
```

脚本至少输出每课的：难度、四段时间预算、正文 CJK 字数、阅读密度（CJK ÷ readingMinutes）、章节/源码行/示例行/变体/积木数、官方 URL 是否带锚点、源码 URL 是否固定 tag/commit 且带行区间、视觉块数/kind/placement/最少步骤/观察重点、最近一条更新日志的 human/ai/pr/commit。异常清单判定阈值见下文。

## 3. 视觉检阅

### 3.1 异常检查（脚本化）

- 每篇 curated 必须有 `visualIndex` 且伴随索引文件存在、双向一致（审计覆盖）。
- 非图片视觉至少 3 步、每步有可验证解释、步骤标签唯一、有观察重点（审计覆盖）。
- placement 必须在正文章数范围内、kind 合法、自定义组件路径存在（审计覆盖）。
- 额外人工项：visual 的 `decision` 必须指向正文中具体的一处学习障碍（「读完仍看不见 X」），而不是泛泛的「让页面更好看」；`caption` 必须声明信息边界与验证入口。

### 3.2 充分性判定（人工）

- **一个视觉块是否足够**：判定标准是「正文中是否存在第二个、且文字无法讲清的独立学习障碍」。若某课正文有多个互不重叠的核心机制（如状态机 + 时间线 + 数值对比），且每个都靠文字难以追踪，应增加视觉块；若其余机制用文字+代码已可验证，一个块足够。视觉块数不是质量指标，**不为凑种类加块**。
- **kind 选择**：同一课题允许不同 kind，但每个 kind 必须对应不同学习障碍；两个视觉解决同一障碍属于冗余，记问题。
- **python 路线**：首轮内容不纳入视觉充分性检阅，重构批次内逐模块判定。
- **检阅基准参考**：`docs/LESSON_REFERENCE_SET.md` 的 langgraph-01-03（graph 拓扑）、torch-01-04（可计算专属组件）、transformer-01-07（tensor + image 双块）作为充分性与 kind 组合的范例。

## 4. 时间预算评估

### 4.1 校准规则

- 四段合计必须严格等于 `estimatedMinutes`（审计强制）。
- **阅读时间**：中文技术正文按 **150–250 字/分钟** 校准（含少量公式与短代码行）。低于 70 字/分钟视为阅读时间高估；高于 300 字/分钟视为阅读时间低估、正文可能过密。
- **源码时间**：按源码节选行数 × 约 2 秒/行 粗估（困难/专家课可放宽到 3 秒/行），`sourceMinutes × 60` 应大于该值。
- **实践时间**：按示例代码行数 × 约 2 秒/行 加复现步骤数量 × 约 2 分钟 粗估，`practiceMinutes × 60` 应大于该值。
- **复盘时间**：困难/专家课至少 10–15 分钟，基础课至少 5 分钟。

### 4.2 评估结论

- 密度异常（<70 或 >300）与示例/源码行数明显超预算的课程记入队列，由作者决定调正文或调预算。
- 调整预算必须同时保持四段合计 = estimatedMinutes；修改课程文件后追加更新日志。

## 5. 状态与深度匹配

- `curated` 必须满足 `depth: deep` 的完整契约（官方入口 + 真实源码 + 分章正文 + 四段时间 + 更新日志 + 视觉决策）。
- 发现 `depth: foundation`（首轮短文：仅导读 + 示例）被标记 `curated` 时，按以下顺序处理：
  1. 判定是否属于「首轮完成待重构」路线（当前仅 Python 有该豁免，且视觉已撤回）。
  2. 不属于豁免时，将该课标记为问题并排入深化批次队列；**不得**继续把它当作已深化内容引用为参考样例。
  3. 状态变更（curated → pending）需用户确认后执行，并在恢复文档记录原因与计数变化。

## 6. 检阅输出与队列管理

- 每次检阅在 `docs/CURRICULUM_RECONSTRUCTION_TARGET.md` 追加一节「存量课程检阅」，记录：检阅日期、覆盖范围与数量、发现的问题清单（按路线/课程）、处理状态、队列链接。
- 问题按严重度分三类：
  - **P1 规则偏差**：源码 URL 用可变分支、curated 与深度不匹配、跨课复制——须修复或明确排期。
  - **P2 历史欠账**：缺更新日志、官方 URL 无锚点但页面本身无子锚点——在下一次实质修改时处理。
  - **P3 建议优化**：时间预算偏宽/偏紧、单课多障碍缺第二视觉——由作者按批次顺带处理。
- 队列是动态清单：修复一项即划掉一项，不得把「已修复」项留在队列中制造重复劳动。

## 7. 修改纪律

- 修改任何专题（正文、视觉、预算、状态）都必须遵守 `CONTRIBUTING.md` 的「课程更新日志与人类 × AI 署名」：
  - 在文末 `## 更新日志` 顶部**追加**新记录（`human` × `ai` 协作对，ai 写本次实际运行模型），`summary` 精确描述本次改动，PR/commit 可核验后回写。
  - **不得覆盖、改写、删除或压缩已有记录**；历史签名（含模型名）是审计事实。
- 视觉文件的修改记录在该课程正文日志中。
