# 源码与官方文档知识图谱

`/source-map` 是独立于课程目录的上游资料导航器。它描述项目本身的结构和证据关系，课程只通过反向链接消费这些节点，不能成为图谱的父级。

## 两张图谱

### 源码图谱

```text
官方仓库
├─ 真实目录
│  ├─ 子目录
│  └─ 文件
│     └─ 已核验函数 / 类 / 常量
└─ tests 等上游范围
```

目录与文件来自路线的官方仓库范围；已经深化的课程会把精确文件和核心符号升级为已核验节点。图谱界面不显示课程模块名，也不按学习顺序排列源码。

### 官方文档图谱

```text
官方文档入口
└─ 官方域名
   └─ URL 路径
      └─ 页面
         └─ 章节锚点
```

页面和章节均保留真实 URL。只有被课程核验过的精确章节才标记为 verified；中间路径节点负责解释官方信息架构，不能伪造不存在的章节标题。

## 数据来源

页面不维护以课程为中心的 `source-map.ts` 清单。`app/pages/source-map.vue` 组合三类既有证据：

1. `track.md` 的官方仓库与文档根入口。
2. `catalog.md` 的真实上游源码范围。这里只读取路径，不读取课程模块标题。
3. 单课 Markdown 解析出的精确源文件、源码符号、官方页面与章节锚点。

源码路径被拆成目录关系，官方 URL 被拆成域名、路径、页面和 hash 关系。课程 ID 仅记录在节点的 `relatedLessonIds` 中，用于右侧 inspector 的“反向学习入口”。

## 课程页如何连接图谱

- 路线页为每一课提供“源码定位 / 文档定位”快捷入口。
- 单课正文的官方章节卡提供文档图谱入口。
- 单课源码页同时提供源码图谱与文档图谱入口。
- 快捷入口通过 `track + mode + q` 定位节点；图谱搜索只保留命中节点和祖先路径。

这形成双向关系：课程能快速进入官方证据，官方节点也能反查已经覆盖它的课程。

## 交互与可访问性

- 节点使用确定性力导向布局，球体表示资料实体，曲线表示父子或包含关系。
- 有子节点的球可折叠；搜索时自动显示命中节点及完整祖先路径。
- 源码 / 文档切换只改变上游证据通道，不改变课程目录。
- 每个可操作节点都使用原生按钮，保留 Tab、Enter 和 Space 行为；完整路径与状态始终在 inspector 中以文字呈现。
- 视觉图谱不能成为唯一入口。所有官方 URL 和关联课程都必须在 inspector 或课程页中提供文本链接。

布局原则参考 D3 force simulation 的 link、repulsion 与 center 模型；SVG 与交互节点同时保留可访问名称。图谱只表达已经登记的官方路径，不能为了让画面更密而生成虚构节点。
