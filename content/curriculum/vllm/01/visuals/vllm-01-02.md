## 视觉实验

### 沿事件时间轴切出四个延迟区间

id: "vllm-01-02-intervals"
kind: "flow"
placement: "chapter:4"
summary: "把一次请求的单调时钟事件摊成时间轴：QUEUED 与 SCHEDULED 之间是排队区间，SCHEDULED 到首 token 是 prefill 区间，首 token 到末 token 是 decode 区间，整段从 SCHEDULED 到末 token 是 inference 区间；同时标出两种 TTFT 的起点。"
caption: "区间由事件时间戳相减得到（stats.py 的 queued/prefill/decode/inference 公式）；图中假定无抢占，抢占会并入所属区间而非重置起点。"
actionLabel: "点亮下一个区间"

#### 步骤

- 事件线 | 展示 arrival=0ms、QUEUED=0.5ms、SCHEDULED=10.5ms、首 token=30.5ms、末 token=150.5ms 五个事件戳。
- 排队区间 | queued_time = SCHEDULED − QUEUED = 10ms，高亮这一段。
- prefill 区间 | prefill_time = 首 token − SCHEDULED = 20ms；服务端 TTFT（arrival 口径）覆盖排队 + prefill 共 30ms。
- decode 区间 | decode_time = 末 token − 首 token = 120ms，四个输出 token 的间隔共三段。
- inference 区间 | inference_time = 末 token − SCHEDULED = 140ms，等于 prefill + decode。
- 两种 TTFT | 服务端直方图取 30ms（含排队），per-request 口径取 20ms（从 SCHEDULED 起算）。

#### 观察重点

- 点亮 decode 区间前先预测：TPOT 分母是输出 token 数还是间隔数。
- 用课程示例的 finish_request 核对全部数字，再插入一次 5ms 抢占，观察 prefill_time 变化。
