#### 步骤

- 输入 | 源码工作的第一道边界是固定 tag、确认构建解释器、定位测试和记录生成文件。 的最小输入和初始状态。
- 模型 | 工作台由版本、构建、测试、证据组成；每条结论都有可复现 tag、路径、命令和最小测试。 中的当前不变量和所有权。
- 主路径 | devguide 建议 Git 获取源码、pydebug 构建并运行 Lib/test；README 和构建脚本连接平台要求与测试入口。 对照源码入口推进一次。
- 失败 | 直接读 main、把系统 Python 当 debug 构建、提交生成文件或不记录命令，会让证据不可复核。 注入失败并记录传播或回滚。
- 边界 | 研究用固定 tag + raw URL，改动用 debug build + targeted test；构建目录与源码分离。 识别工程和版本取舍。
